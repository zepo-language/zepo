# Zepo 0.x: Fibers, Workers, and Channels

Zepo is a Scheme-flavored Lisp written in Zig with a bytecode VM and a generational GC. The 0.x line just grew a two-layer concurrency story I want to show off, because the API surface is small and the layers compose cleanly.

## Two layers, one channel API

```
            ┌──────────────────────┐
            │   Cooperative fibers │     same VM, same heap
            │   (poll(2) scheduler)│     yield at I/O, sleep, yield
            └──────────┬───────────┘
                       │
                  Channels (FIFO, blocking)
                       │
            ┌──────────┴───────────┐
            │   OS-thread workers  │     fully isolated VMs
            │   (own GC + globals) │     portable values only
            └──────────────────────┘
```

Two primitives, one inbox.

- **Fibers** share an OS thread and a heap. Cheap to spawn, cheap to yield. Useful when the bottleneck is I/O or you want concurrent control flow without locks. `spawn`, `yield`, `sleep`, `fiber-join`.
- **Workers** are real OS threads, each with its own VM — independent GC, independent symbol table, independent globals. Useful when you actually want CPU parallelism. `spawn-worker`, `worker-alive?`, `worker-stopping?`.
- **Channels** look the same to both. Bounded, blocking, FIFO. `make-channel`, `channel-send!`, `channel-recv!`. Only portable values cross thread boundaries (numbers, strings, symbols, lists, vectors, and hash tables of portable values) — pointers stay home; the value is deep-copied into the receiver's heap.

Worker code starts life as *data*, not a live closure — that's exactly what isolation requires, since a compiled closure captures pointers into the parent's heap and we explicitly don't let those cross. You hand the worker either a source string or a **quoted/quasiquoted form**, and the worker compiles it on arrival with `eval`. The nice part: quasiquote lets you capture values *by value*, splicing them straight into the form:

```scheme
(define factor 6)
(spawn-worker `(lambda (out) (channel-send! out (* 7 ,factor))) out)
```

`,factor` becomes the literal `6` inside the form before it's sent. No shared heap, no pointers crossing the boundary — just data that happens to be code. And because forms travel over channels too, a long-lived worker can be fed new code to `eval` mid-run.

## A worker pool

Here's the whole thing — a pool of 4 OS-thread workers squaring 20 numbers in parallel, sorted on the way out.

```scheme
(define N-WORKERS 4)
(define N-JOBS    20)

(define jobs    (make-channel 32))
(define results (make-channel 32))

; Worker body: read a number, square it, send it back. #f = shutdown.
(define worker-code
  "(lambda (jobs out)
     (let loop ()
       (let ((x (channel-recv! jobs)))
         (when x
           (channel-send! out (* x x))
           (loop)))))")

; Spawn the pool.
(define workers
  (let loop ((i 0) (acc '()))
    (if (= i N-WORKERS) acc
        (loop (+ i 1)
              (cons (spawn-worker worker-code jobs results) acc)))))

; Submit jobs.
(let loop ((i 0))
  (when (< i N-JOBS)
    (channel-send! jobs i)
    (loop (+ i 1))))

; Collect results (order may differ from submission).
(define out
  (let loop ((n 0) (acc '()))
    (if (= n N-JOBS) acc
        (loop (+ n 1) (cons (channel-recv! results) acc)))))

(for-each (lambda (r) (display r) (display " ")) (sort out <))
(newline)

; Shutdown: one sentinel per worker, then drain.
(let loop ((i 0))
  (when (< i N-WORKERS)
    (channel-send! jobs #f)
    (loop (+ i 1))))
(let loop ((ws workers))
  (when (pair? ws)
    (let wait () (when (worker-alive? (car ws)) (sleep 0.01) (wait)))
    (loop (cdr ws))))
```

Output:

```
0 1 4 9 16 25 36 49 64 81 100 121 144 169 196 225 256 289 324 361
```

End-to-end wall-clock — including process startup, spawning 4 pthreads, 20 round-trips across two channels, and draining the pool — is about **10 ms** on an M-series Mac (measured over 10 runs, every one rounding to 0.01 s under `time -p`). Nothing here is doing real work; that number is dominated by thread spawn cost. The point is that the *cost of saying it* is small.

## What's notable about the design

A few things landed nicely.

- **The channel API is identical for fibers and workers.** Same `(make-channel N)`. Same `channel-send!`. Same `channel-recv!`. Code that works between fibers ports unchanged to workers. The runtime uses `c_allocator` on the channel itself so the storage doesn't depend on either VM's GC.
- **Workers can't see each other's heaps.** That sounds like a constraint until you've debugged a multi-threaded GC. Portable-values-only is a hard rule, enforced at marshal time, and it eliminates an entire class of race.
- **Cooperative shutdown is observable.** A worker can call `(worker-stopping?)` (a zero-arg primitive that reads the parent VM's stop flag) and exit cleanly when the parent decides it's done. The sentinel pattern in the example is one way; the stop flag is the other.

## What's not here yet

- **No `select`** across multiple channels. Coming.
- **No structured cancellation.** You shut workers down with sentinels or by waiting on `worker-alive?`. Fine for the patterns we have; will get tighter.

```sh
git clone https://github.com/<...>/zepo

zig build install-global -Doptimize=ReleaseFast

```
